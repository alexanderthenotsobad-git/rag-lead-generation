      Technical spec & revision log
      

        
Architecture

        

          Served by gui_server.py. The browser calls local
          /api endpoints; the server loads keys from .env
          and calls each provider. The pipeline mirrors rag_leads/:
          discover restaurants, fetch reviews, gate by rating and keyword, embed
          with MiniLM (384 dims), upsert to Pinecone, retrieve the query, classify
          complaints with DeepSeek, and generate one pitch per restaurant.
        

        

          Run python gui_server.py from the repo root, then open
          http://127.0.0.1:8080.
        


        
Zoning

        

          The pipeline requires a rectangle. The ZIP is geocoded with Google and
          its viewport supplies low (southwest) and
          high (northeast). This is the same shape used by
          DEFAULT_BOX and SANTA_MONICA_BOX in
          rag_leads/config.py.
        


        
Gate order

        
    
          
  1. Rating: 1–3 stars are complaint candidates; 4–5 are praise.
    2. 
          
  2. Keyword: allergen, ingredient, or dietary term must appear.
    3. 
          
  3. Classifier: DeepSeek returns COMPLAINT / PRAISE / IRRELEVANT with a quote.
    4. 
        

        
Only COMPLAINT reviews feed the pitch prompt. Otherwise the output is No relevant pain points found.


        
Errors

        

          Every API card owns a status line. HTTP status, provider message, and
          network/CORS failures are written there and in the progress log.
